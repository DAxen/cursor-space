2.1 方法一：LLM Wiki（Obsidian / Markdown 知识库）

一句话原理：知识写成互相链接的 Markdown + 一个目录页，Agent 像人查"带目录的手册"——先读目录、再读相关页；知识编译一次、持续保鲜，而非每次查询临时检索合成。（Karpathy 2026.04 规范化，单 gist 5000+ star）
三层架构 + 三个工作流
适用场景
  • 业务背景、架构决策（ADR）、编码约束、模块职责、坑清单、术语表——所有"需要人评审的高价值知识"
  • 知识量在几百页 / 约十万 token 内导航最优
✓ 优势
  • 零基础设施（git 里的文件）
  • 人与 Agent 读同一份，可评审/可 diff/可溯源
  • 与 agentic search 零摩擦
  • 可解释性最强，改文件即更新
△ 劣势
  • 需人工策展纪律，有腐化风险
  • 不擅长"谁调用谁"等结构性查询
  • 几千页后目录导航吃力
  • 没写进去的它不知道
