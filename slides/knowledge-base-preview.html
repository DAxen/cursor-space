复用 PostgreSQL；规模适中、希望减少新组件时优先。

Milvus

面向大规模分布式向量检索，能力强但运维更复杂。

第三部分｜项目知识库落地思路09 / 11

落地方案｜知识、检索、代码图、Agent 四条链协同

原则：先治理、再检索；先评测、再图谱；权威源与派生索引分离，避免“一上来堆数据库”。
1

知识治理链

输入：CLAUDE.md、Skills、Specs、Docs、ADR

动作：分类去重、Owner、适用路径、版本、审核状态、来源

产出：Git 中可信的知识本体 + LLM Wiki 派生层

权威源不被 AI 摘要覆盖
2

混合检索链

召回：Metadata Filter + BM25/Sparse + Dense

精排：RRF + Cross-Encoder/Reranker

产出：带来源、版本与相关度的 Top-K 文档

Qdrant / pgvector / OpenSearch 三选一优先
3

C/C++ 代码智能链

输入：compile_commands.json + Git

提取：Definition / Reference / Call / Include / Inheritance

产出：符号上下文、调用链、影响范围、相似实现

Clang/clangd 优先于 LLM 自动猜图
4

Agent 接入与验证链

入口：AGENTS.md / CLAUDE.md / prepare-change Skill

工具：MCP 构建 Context Pack

闭环：OpenSpec → 编码 → Build/Lint/Test/Sanitizer

“知道什么是对的” + “阻止错误通过”
第一版建议：Git Markdown + OpenSpec + 一个混合检索后端 + Clang 符号服务 + MCP；Neo4j 在多跳查询价值被验证后引入。

每一阶段都用历史真实任务验证 检索是否更准、首轮成功率是否提高；没有增益的复杂技术不进入生产。
