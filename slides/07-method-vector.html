2.3 方法三：向量数据库（Embedding RAG）

一句话原理：文档/代码切块 → 每块转成高维向量（"语义指纹"）入库；查询也转成向量，找"指纹最接近"的块。本质是"按意思找"而非"按字面找"——搜"鉴权"能命中只写了 login validation 的代码。
原理流程示意
适用场景
  • 不知道确切符号名的概念性检索；spec 术语与实现术语不一致
  • 超大规模陌生仓库冷启动定位
  • 海量非代码知识（历史 issue、评审记录、聊天记录）检索
✓ 优势
  • 海量异构内容伸缩性最好（百万级块）
  • 建库全自动，无需人工策展
  • 模糊 / 跨术语查询独一档
△ 劣势
  • 代码检索精度不足
  • 索引保鲜是持续负担
  • 黑盒难调试；有基础设施成本
  • 私有仓需评估代码出境安全
代表工具
Milvus / Zilliz Qdrant Pinecone Turbopuffer（Cursor 后端） sqlite-vec（本地轻量） claude-context（MCP 插件）
最佳实践：BM25 + 向量 + 重排器（reranker）混合检索，以 MCP 插件形式供 Agent 按需调用
