1.3 案例三：DeepWiki（Cognition / Devin）—— 自动生成的代码仓 Wiki

结论：对大型仓库，"预消化"的知识层（更小、更干净、可导航的 Markdown 制品）能显著提升 Agent 理解效率——Devin 问答先查 Wiki 再定位代码；Google CodeWiki、Greptile、微软 deep-wiki skill 同属此路线。
知识管理方式
  • 自动分析仓库结构 → LLM 生成架构图（Mermaid）、组件表、时序图的 wiki 页面
  • 每个论断带 file:line 引用锚点，可回溯到源码
  • PR 合并后自动更新，保持与代码同步
  • 支持 .devin/wiki.json 人工"导演"：指定页面结构与重点，替代全自动规划
  • 生成 llms.txt / AGENTS.md 导航文件，作为 Agent 的"地图入口"
同路线工具
Google CodeWiki（2025.11） Greptile（图感知摘要） DeepWiki-Open（开源） microsoft/agent-skills deep-wiki（可自部署）
启示
这是"Obsidian / LLM Wiki 思路"的工业化验证；但要记住实证结论：自动生成打底、人工策展定稿——手写的上下文文件效果优于纯自动生成。
